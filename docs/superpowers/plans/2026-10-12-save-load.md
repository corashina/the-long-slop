# Browser Save and Load Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore browser sessions without losing the prior save or active session after a failure.

**Architecture:** Rust captures and validates logical snapshots, then reconstructs a separate runtime. JavaScript stores one structured record in IndexedDB. The app replaces prepared runtime and presentation state at one frame boundary.

**Tech Stack:** Rust, serde 1.0.229, serde_json 1.0.151, Rapier 0.36.0, Bevy 0.19.1, wasm-bindgen 0.2.129, browser IndexedDB, Web Crypto, Node tests.

**Spec:** `docs/superpowers/specs/2026-10-12-save-load-design.md`

## Global Constraints

- Use one manual save slot and IndexedDB.
- Support only the current schema and current source export.
- Reject incompatible saves. Do not add migrations or compatibility paths.
- Store world positions as absolute `[f64; 3]` coordinates.
- Preserve the previous save when a write fails.
- Preserve the active session when a load fails.
- Allocate snapshot and candidate data only during save or load operations.
- Implement only critical tests. Reuse existing fixtures and dependencies.
- Read the project AGENTS.md. Use stop-slop for UI text and documentation.
- Keep source assets out of Git. Keep other chats' checkouts unchanged.

## Review Focus

- Large source path IDs, seeds, and station indices must survive JavaScript without integer rounding. Task 1.
- A late storage or preparation result after cancellation must not replace the active session. Tasks 5 and 6.
- A walking player far from the parked car needs terrain support at both locations. Tasks 3 and 4.
- A lamp snapshot at the cycle wrap must preserve the visible phase and next update. Task 2.
- A second tab can block database access; Continue and New game must remain usable. Tasks 5 and 7.

## Task 1: Current-schema contract and stable identity

**Files:** Create `src/save.rs`, `src/save/schema.rs`, `src/save/identity.rs`, `src/save/validate.rs`, `tests/save_schema.rs`. Modify `src/lib.rs`.

**Interfaces:**
- `SAVE_SCHEMA_VERSION: u32 = 1`.
- `SourceKey { file: String, path_id: String }`; decimal `path_id` resolves to the manifest's signed source path ID.
- `InstanceId`: tagged `Initial { source: SourceKey }` or `Station { seed: String, index: String, role: String }`.
- `SourceStamp { app_id: u32, build_id: u32, manifest_sha256: String, source_hashes: Vec<SourceHash> }`.

- `ProgressSnapshot { trip_m: f64 }`; `PlayerSnapshot.pose: AbsolutePose`; `WorldSnapshot.seed: String`.
- Define typed DTOs for player, carry, vehicle, engine, items, attachment locations, mechanisms, openings, cycle, controllers, switches, world records, progress, and view.
- `CameraSave` is a tagged first-person or chase value, independent of Bevy types.
- `SaveError` distinguishes corrupt data, incompatible sources, invalid links, reconstruction failure, and missing assets.
- `IdentityMap::new(reference: &ReferenceManifest) -> Result<Self, SaveError>` resolves source and instance keys to current runtime IDs.
- `SaveSnapshot::from_json(bytes: &[u8]) -> Result<Self, SaveError>`.
- `SaveSnapshot::validate(&self, reference: &ReferenceManifest, expected: &SourceStamp) -> Result<(), SaveError>`.
